1. INTRODUCTION                                                  *prigh-intro*

prigh.nvim talks to `prigh acp` (or any agent speaking the Agent Client
Protocol, https://agentclientprotocol.com) over stdio. The agent reads and
writes files through Neovim, so it sees your unsaved buffers and its edits
land in them. Requires Neovim 0.10 or newer; no other plugins.

==============================================================================
2. SETUP                                                         *prigh-setup*

>lua
    require("prigh").setup({
      cmd = { "prigh", "acp" },
      -- a remote backend:
      -- cmd = { "prigh", "acp", "-connect", "host:7777", "-token", "T" },
    })
<
The commands exist without calling setup(); setup() applies the options and
adds the global keymaps. Run |:checkhealth| prigh to check the installation.

==============================================================================
3. COMMANDS                                                   *prigh-commands*

:Prigh                                                                *:Prigh*
    Toggle the chat. The first time it starts the agent and loads the last
    session of the directory (|prigh-options| resume_last) or a new one.

:PrighNew                                                          *:PrighNew*
    Start a new session.

:PrighSessions                                                *:PrighSessions*
    Pick a session of this directory to load (its history is replayed into
    the chat), or a new one. The current one is marked with ●.

:[range]PrighAdd [diagnostics|clear]                               *:PrighAdd*
    Attach to the next prompt: the current buffer with its unsaved text, or
    with a [range] those lines (path and line range), or with "diagnostics"
    the buffer's (or range's) diagnostics. "clear" drops the attachments.
    Attachments are listed in the prompt's bar.

:PrighCancel                                                    *:PrighCancel*
    Cancel the running turn. Queued prompts go back to the prompt buffer.

:PrighMode                                                        *:PrighMode*
    Pick the session mode.

:PrighModel                                                      *:PrighModel*
    Pick the model.

:PrighConfig [id]                                                *:PrighConfig*
    Pick one of the agent's config options (model, thinking, ...) and its
    value, or with [id] (or a category, e.g. "thought_level") that option.

:PrighReview                                                    *:PrighReview*
    Review the files the agent wrote since the last review, hunk by hunk
    (|prigh-review|).

:PrighLog                                                          *:PrighLog*
    Show the log: the agent's stderr, the protocol traffic and errors.

:PrighRestart                                                  *:PrighRestart*
    Restart the agent and reload the current session.

4. KEYS                                                             *prigh-keys*

Global keys, under the prefix (default <leader>p; `keymaps = false` disables
them, or set any key to false):

    <prefix>p   toggle the chat              (:Prigh)
    <prefix>n   new session                  (:PrighNew)
    <prefix>s   sessions                     (:PrighSessions)
    <prefix>a   attach buffer / selection    (:PrighAdd)
    <prefix>d   attach diagnostics           (:PrighAdd diagnostics)
    <prefix>x   clear attachments            (:PrighAdd clear)
    <prefix>c   cancel the turn              (:PrighCancel)
    <prefix>m   mode                         (:PrighMode)
    <prefix>M   model                        (:PrighModel)
    <prefix>o   config options               (:PrighConfig)
    <prefix>r   review changes               (:PrighReview)
    <prefix>l   log                          (:PrighLog)

Chat window:                                                   *prigh-chat-keys*

    q           close the chat
    <Tab>       expand/collapse the thought or tool output under the cursor
    <CR>        open the location (↳ path:line) under the cursor
    i a o       go to the prompt
    <C-c>       cancel the turn
    g?          show the keys

Prompt buffer:                                               *prigh-input-keys*

    <CR>        (normal) send; queued while a turn runs
    <C-s>       (normal, insert) send
    <C-c>       (normal, insert) cancel the turn
    q           close the chat
    g?          show the keys
    @           (insert, at the start or after a space) complete a file
    /           (insert, at the start) complete a slash command

Permission cards: see |prigh-permissions|. Review: see |prigh-review|.

==============================================================================
5. THE CHAT                                                         *prigh-chat*

The chat is a buffer (filetype "prigh", highlighted as markdown) with the
prompt buffer (filetype "prigh_input") below it. It shows:

  ## You / ## prigh   your prompts and the agent's streamed answers
  ▸ Thinking: ...     the agent's thoughts, dimmed and collapsed (<Tab>)
  ✓ title · kind · status   tool calls (○ pending, ◐ running, ✓ done,
                      ✗ failed) with their locations (↳ path:line, <CR>
                      opens), diffs, and collapsed output (<Tab>)
  Plan                the agent's plan
  ℹ ⚠ ✗               notices: the agent's, stop reasons, errors with what
                      to do next, the files changed in a turn
  ⏸ queued: ...       prompts waiting for the running turn

Prompts: "@path" mentions of existing files are sent as resource links.
A prompt starting with an unknown "/command" is refused with the closest
commands. Prompts sent while a turn runs are queued and sent in order; a
cancel puts them back in the prompt buffer.

==============================================================================
6. PERMISSIONS AND QUESTIONS                                 *prigh-permissions*

When the agent asks permission (session/request_permission) the chat opens
and a card shows the tool, its locations and the diff of an edit (cut after
`permission.inline_diff_max` lines). The card owns the keyboard until it is
answered:

    a           allow once          A   always allow
    r           reject              R   always reject
    1-9         the option with that number
    <CR>        the option under the cursor
    d           the full diff in a float (q closes it)
    <Esc>       cancel the request
    <C-c>       cancel the request and the turn

Other chat keys say to answer first. Several requests are asked one after
the other.

Questions (elicitation/create, form mode) are asked field by field with
|vim.ui.select()| and |vim.ui.input()|, then shown for review: Submit, Edit
again, Decline or Cancel. <Esc> on any field cancels.

==============================================================================
7. FILES THE AGENT EDITS                                          *prigh-files*

The agent reads files through Neovim: a loaded buffer's text, unsaved
changes included; other files from disk.

When it writes a file that is loaded, the buffer is changed in place (only
the changed lines, as one undo step: |u| undoes the agent's edit) and then
written with `:noautocmd write` so the agent's shell commands see it
(`fs.save_after_write`; `fs.write_autocmds = true` runs BufWritePre/Post
autocommands such as formatters). Files not loaded are written to disk.

Auto-save plugins: the review never changes the buffer until it is done, but
an auto-save plugin can still write a buffer while you review it. During a
review `b:prigh_review` is true; make your plugin skip such buffers, e.g. for
auto-save.nvim:
>lua
    condition = function(buf) return not vim.b[buf].prigh_review end
<
==============================================================================
8. REVIEWING CHANGES                                             *prigh-review*

Every file the agent writes is recorded with its text from before the first
write. After a turn the chat lists the changed files. |:PrighReview| picks
one (with +added −removed counts) and opens it with the change as hunks:
removed lines as virtual lines above, added lines highlighted.

    ]h  [h      next / previous hunk
    ga          accept the hunk (keep the agent's text)
    gr          reject the hunk (restore the old text)
    gA  gR      accept / reject all remaining hunks
    q  <Esc>    leave the review without changing anything

When every hunk is decided, the rejected hunks are reverted in one batch
(one undo step), the file is saved, and the next changed file is offered.
Editing the buffer during the review re-diffs it against the old text,
keeping the decisions on unchanged hunks; insert mode pauses the review.

==============================================================================
9. STATUS LINE                                               *prigh-statusline*

The chat's winbar shows the session title and what the agent reports: model,
thinking level, mode, approval mode, plan mode, context use, cost, whether a
turn runs, queued prompts, subagents, jobs, reminders, goal and pending
permission requests. prigh sends these in its `_prigh/state` notification;
other agents' config options, modes and usage_update are shown too.

For other status lines:
>lua
    require("lualine").setup({
      sections = { lualine_x = { require("prigh").statusline } },
    })
<

10. OPTIONS                                                     *prigh-options*

>lua
    require("prigh").setup({
      cmd = { "prigh", "acp" },   -- the agent command
      env = nil,                  -- extra environment for the agent
      cwd = nil,                  -- session directory (default: :pwd)
      resume_last = true,         -- load this directory's last session
      keymaps = {                 -- or false
        prefix = "<leader>p",
        toggle = "p", new = "n", sessions = "s", add = "a",
        diagnostics = "d", clear_context = "x", cancel = "c",
        mode = "m", model = "M", config = "o", review = "r", log = "l",
      },
      chat = {
        position = "right",       -- right | left | top | bottom
        width = 0.4,              -- fraction of the editor, or columns
        height = 0.4,             -- for top/bottom
        input_height = 6,
        tool_output_lines = 0,    -- tool output shown before collapsing
        diff_max_lines = 40,      -- longer diffs are collapsed
        thoughts_collapsed = true,
      },
      permission = { inline_diff_max = 20 },
      fs = { save_after_write = true, write_autocmds = false },
      log = { max_lines = 5000, traffic = true },
    })
<

12. LUA API                                                         *prigh-api*

require("prigh").statusline()           the state as one line
require("prigh.complete").items(kind, base, { cwd, commands })
                                        completion items ("file"/"command"),
                                        for completion plugins
require("prigh.review").open({ buf, before, after?, title?, on_done? })
                                        the hunk review on any buffer: the
                                        buffer holds the new text (or
                                        `after` is put in it); on_done gets
                                        { status, accepted, rejected }
